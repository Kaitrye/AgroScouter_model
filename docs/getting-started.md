# Запуск и проверка

Комплект рассчитан на Ubuntu 24.04, ROS 2 Jazzy и Gazebo Harmonic (gz-sim 8). Команды выполняются из корня репозитория.

## Быстрый запуск

Перейдите в корень клонированного репозитория. Запускайте скрипты через `bash`:
это работает и из оболочки fish.

Если пакет ROS-моста или инструменты сборки ещё не установлены:

```bash
sudo apt update
sudo apt install ros-jazzy-ros-gz cmake g++
```

Это дополнения к уже установленному ROS 2 Jazzy. Скрипт ожидает его
в `/opt/ros/jazzy`. Установка самого ROS 2 описана в документации ROS.

Первый терминал — симулятор, мосты, TF камеры, лидара и IMU, обработчик команд:

```bash
bash start_sim.sh
```

При первом запуске скрипт собирает небольшой плагин анимации гусениц в
`build/track_animation`. После изменения его исходников он пересобирается
автоматически.

Второй терминал, из той же папки:

```bash
bash teleop.sh
```

Клавиши управления выводятся в окне терминала: `i` — вперёд, `,` — назад,
`j`/`l` — поворот, `k` или пробел — остановка. Держите клавишу движения нажатой;
окно этого терминала должно быть активным. Поддерживаются английская и русская
раскладки. Команды повторяются с частотой
10 Гц и обнуляются через секунду после последнего нажатия. Скорость также
ограничена моделью.
Остановите симуляцию через Ctrl+C в первом терминале.

Без графического окна, с теми же ROS-топиками:

```bash
bash start_sim.sh gui:=false
```

Чтобы отдельно посмотреть модель без ROS-моста:

```bash
bash start_gazebo.sh
```

Для такого режима ROS-топики не создаются. Управление из `teleop.sh`
появится только при запуске через `start_sim.sh`.

## Первая проверка

Оставьте `start_sim.sh` запущенным, убедитесь, что мир не на паузе, и закройте
телеуправление, чтобы команды не конфликтовали. В другом терминале:

```bash
bash check_motion.sh
```

Робот должен проехать вперёд, остановиться, повернуться и снова остановиться.
Проверка занимает около 13 секунд симуляционного времени. Она проверяет
изменение **истинной позы**, направление движения, остановку и приход кадров
камеры, лидара и IMU. Последняя строка содержит `PASS=True` или `PASS=False`.
Это проверка запуска, а не калибровка реальной динамики.

## Если что-то не запускается

- `ros2` или пакет `ros_gz_bridge` не найден: проверьте ROS 2 Jazzy и установку
  пакетов выше. Скрипты сами загружают `setup.bash`.
- Модель не найдена: запускайте скрипты из корня репозитория; они задают
  `GZ_SIM_RESOURCE_PATH` относительно своего расположения.
- Робот виден, но не движется: проверьте, что мир не на паузе, посмотрите вывод
  первого терминала, особенно ошибки `TrackController` и физического движка.
  Гусеничный привод требует поддержки изменения контактной поверхности
  в DART / gz-physics. На нестандартной или старой установке DART эта
  возможность может отсутствовать. Проверьте лог запуска; замена привода
  произвольным перемещением позы исключит контактную физику.
- Чёрное или отсутствующее изображение: проверьте сообщения `Sensors` / Ogre2.
  Можно временно перейти на простую визуализацию и уменьшить разрешение.
- Уточнение массы и трения не требует переделки геометрии: измените JSON,
  запустите генератор и повторите проверку движения.
