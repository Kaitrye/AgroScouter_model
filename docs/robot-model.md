# CAD и модель робота

Исходная модель, предоставленная для репозитория: [`cad/robot_model_stp.STEP`](../cad/robot_model_stp.STEP). Это неизменённая копия файла пользователя. Экспортированные STL уже включены в проект; FreeCAD для запуска симуляции не нужен.

**SHA-256 STEP:** `eb9b9a188430487cf9e57302da720949f1a7edfcbce387864024570d42a7cb8c`. В метаданных экспорта [`config/geometry.json`](../config/geometry.json) осталось исходное имя файла `robot_model_stp (1).STEP`.

## Что получено из CAD

Система координат симуляции: X вперёд, Y влево, Z вверх, единицы — метры.
В STEP единицы — миллиметры; исходная ось Y направлена вверх.
Преобразование: `X_ros = (Z_cad + 201.458483) / 1000`,
`Y_ros = (X_cad - 595) / 1000`,
`Z_ros = (Y_cad + 76.445175) / 1000`.

| Величина | Значение | Основание |
|---|---:|---|
| Общая длина по внешней геометрии | около 0.68 м | CAD и передний жёлтый выступ |
| Общая ширина | около 0.966 м | CAD, включая выступающие детали |
| Общая высота | около 0.817 м | открытая рама после удаления верхнего блока CAD |
| Расстояние между центрами лент | 0.810125 м | CAD |
| Ширина каждой ленты | 0.120 м | CAD |
| Внешняя длина ленты | 0.472134 м | CAD |
| Внешняя высота ленты | 0.324818 м | CAD |
| Камера: X, Y, Z относительно base_link | 0.271, 0.236, 0.592 м | нижняя грань корпуса в `camera_mount.blend` |
| IMU: размер корпуса | 60 × 48 × 16 мм | условная прямоугольная модель на переднем торце пластины |

Направление «вперёд» сохранено вдоль исходной +Z CAD. Это интерпретация
геометрии: проверьте её при доступе к роботу. По фотографиям верхняя часть
рамы открыта: сплошная крышка и антенно-камерный блок удалены из сетки.
Жёлтая площадка продолжена вперёд за раму; с её левого края выступает компактное зелёное
крепление с небольшой камерой, смотрящей вертикально вниз. Видимая форма крепления взята
из отредактированного `camera_mount.blend`. Оптический центр поставлен на 1 мм ниже нижней
грани чёрного корпуса камеры; это допущение, а не измеренная характеристика. Боковые камеры, большая камера и лидар удалены из отображаемой сетки. На боках
оставлены только цилиндрические моторы; манипулятор и мелкие детали внутри нижней
части корпуса также убраны. Активна одна нижняя виртуальная камера.

`config/geometry.json` содержит размеры и преобразование координат.
`config/cad_parts.json` содержит имена и исходные габариты 637 конечных
компонентов сборки; компонент основного шасси сам содержит 309 твёрдых тел.
Компьютер, контроллер и аккумулятор на жёлтой площадке сохранены. Мелкий
крепёж и электронные детали внизу корпуса, манипулятор и боковые приставки
опущены в визуальной сетке. Отображаемые STL имеют около 163 тысяч
треугольников суммарно. Исходная STEP-сборка при этом сохранена без изменений. В расчёте столкновений используются простые формы.

Цвета видимых деталей взяты с фотографий в `images`: серебристый каркас, чёрные гусеницы и цилиндрические моторы, жёлтая площадка, синий аккумулятор
и зелёное крепление камеры. Стеклянные панели полупрозрачны. Палитра находится в
`config/parameters.json`. Для окраски исходный `body.stl` разделён на
несколько сеток по материалам; после замены исходного STL запустите
`python3 tools/colorize_mesh.py`, затем `python3 tools/generate_model.py`.

Жёлтая передняя пластина сохранена длиной 190 мм и сужена с 430 до 280 мм.
Её боковые края не доходят до косых опор металлической рамы; весь узел сдвинут
вперёд на 5 мм, чтобы освободить заднюю кромку. IMU и камера с зелёным
креплением сдвинуты вместе с пластиной и сохраняют прежние расстояния до её краёв.

На переднем краю жёлтой площадки по центру установлен прямоугольный IMU-корпус
размером 60 × 48 × 16 мм. Его геометрия условная; электроника IMU в Gazebo не
симулируется. Зелёное крепление, корпус камеры и датчик сгруппированы и подписаны
в `camera_mount.blend` и `robot_visual_edit.blend`.

## Изменение крепления камеры

[`camera_mount.blend`](../camera_mount.blend) — отдельный редактируемый источник
геометрии площадки, зелёного крепления, корпуса камеры и IMU. Его начало координат —
центр жёлтой площадки; в роботе эта точка находится в `(0.245, 0, 0.607)` м
относительно `base_link`. После сохранения изменений в Blender выполните из
корня проекта:

```bash
bash tools/sync_camera_mount.sh
```

Сценарий экспортирует четыре STL (площадка, крепление, камера и IMU), обновляет положение виртуальной камеры
в `config/parameters.json`, пересоздаёт `models/robot/model.sdf`, обновляет
[`robot_visual_edit.blend`](../robot_visual_edit.blend) и проверяет ресурсы.
Отдельная Blender-модель не содержит оптического маркера: положение камеры
вычисляется по нижней грани чёрного корпуса. Если оптический центр должен быть
в другом месте, поправьте `camera.pose_m_rad` вручную после экспорта.

## Предварительная физика

| Параметр | Начальное значение |
|---|---:|
| Масса корпуса с оборудованием (предварительная оценка) | 32 кг |
| Масса каждого гусеничного модуля | 4 кг |
| Суммарная масса | 40 кг |
| Трение: продольное / поперечное | 1.0 / 0.7 |
| Коэффициент эффективности поворота | 0.8 |
| Максимальная линейная скорость | 0.4 м/с |
| Максимальная угловая скорость | 0.6 рад/с |
| Максимальное линейное ускорение | 0.4 м/с² |
| Максимальное угловое ускорение | 0.8 рад/с² |
| Таймаут входных команд | 0.5 с |

**Это допущения, а не характеристики реального робота.** Масса 40 кг выбрана
как стартовая для этой геометрии. Центр масс корпуса оценён по объёмам CAD
при условии одинаковой плотности; настоящие материалы и массы неизвестны.
Инерции рассчитаны для однородных прямоугольных объёмов с заданными массами.
Они положительные и согласованы с размерами, но не являются измеренными.

Гусеницы моделируются через `TrackedVehicle` и по одному `TrackController`
на сторону: движение обеспечивается скоростью контактной поверхности.
Ленты жёстко соединены с корпусом. Поверх CAD-модели движутся визуальные
траки по внешнему треугольному контуру, который генератор извлекает из STL
каждой гусеницы. Их скорость берётся из команд для левой и правой сторон, поэтому при
повороте стороны анимируются независимо. Эти траки не имеют массы и контакта;
физику движения по-прежнему рассчитывает `TrackController`. Колёса остаются
неподвижными, отдельных шарниров между звеньями ленты нет. Деформация, натяжение,
грунтозацепы и момент моторов не моделируются. Это упрощённая модель для
работы с управлением и локализацией, не для исследования механики гусениц.

Форма контакта каждой стороны — нижняя капсула (бокс и два цилиндра)
и верхний бокс. Конверсия боксов корпуса сохраняет его общий габарит,
но заполняет пустоты рамы: проникновение предметов внутрь корпуса в этом
варианте не воспроизводится. Внутренние детали и манипулятор не моделируются отдельными коллизиями.
Актуальный вид модели в тестовой сцене Gazebo показан на [цветном снимке v2](../images/preview_colored_v2.png).
Гусеницы в прежнем диагностическом изображении [`preview.png`](../images/preview.png)
показаны целым боксом; фактический контакт в SDF — капсула. Это изображение
было создано до изменения верхней части модели и не показывает текущий вид.
